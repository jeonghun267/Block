# 승인된 보안 검증 절차

BlockTrade 보안 검증은 소유권과 범위가 명확한 비운영 환경에서만 수행합니다.

## 자동 검사

- 정적 검사와 빌드
- API 요청 크기·속도 제한
- 인증 누락 시 fail-closed
- 조직 간 객체 접근 차단
- Maker–Checker 자기 승인 차단
- 주문·출금 경로 부재 확인
- 비밀정보·토큰 로그 유출 검사
- 전략 원본의 구매자 응답 노출 검사
- 감사 해시 체인과 작업 재시도 불변성

## Strix 사용 경계

Strix 같은 공격적 보안 도구는 자동 배포 단계에서 운영 사이트에 실행하지 않습니다.

1. 대상은 별도 Staging URL과 테스트 전용 D1/KMS 계정으로 제한합니다.
2. 거래소는 모의 어댑터와 무가치 테스트 자격증명만 사용합니다.
3. 허용 호스트, 시간, 요청률, 금지 경로와 중단 연락처를 서면으로 기록합니다.
4. 데이터 파괴, 대량 부하, 사용자 가장과 제3자 거래소 공격을 금지합니다.
5. 발견 사항은 재현 단계, 영향, 증거와 수정 회귀 테스트로 남깁니다.
6. Critical/High가 열려 있으면 실거래 승격을 차단합니다.

## 수동 출시 게이트

- 외부 침투 테스트와 재검증
- Cloudflare·IdP·KMS 감사 로그 수집 확인
- 키 회전·폐기 훈련
- stale data, 거래소 지연, 중복 이벤트, Worker 재시작 복구 훈련
- Kill Switch와 미체결 주문 확인 훈련
- WORM 증적과 사고보고 Runbook 확인

보안 도구의 결과는 통과 인증서가 아니라 특정 시점의 증거입니다. 코드, 인프라 또는 거래소 권한이 바뀌면 다시 검증합니다.
